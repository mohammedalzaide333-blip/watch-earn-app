# مِشاهدة — موقع "شاهد واربح"

موقع كامل (Backend + Frontend + قاعدة بيانات) يتيح للمستخدم إنشاء حساب، مشاهدة إعلانات، وتجميع رصيد، مع نظام سحب.

## ما يحويه المشروع
- **Backend**: Node.js + Express
- **قاعدة البيانات**: PostgreSQL (خارجية، مستقرة — لا تُمسح عند إعادة نشر الخادم)
- **تسجيل الدخول**: حسابات حقيقية (bcrypt لتشفير كلمات المرور + JWT للجلسات)
- **حماية من الغش**: توقيت مشاهدة الإعلان يُحسب من قاعدة البيانات لا من المتصفح، مع قفل صفوف (row locking) يمنع التلاعب بالطلبات المتزامنة، وهناك حد أقصى لعدد المشاهدات بالساعة
- **Frontend**: صفحة واحدة HTML/CSS/JS عادية (بدون إطار عمل)، تصميم عربي RTL

## الخطوة الأولى: إنشاء قاعدة بيانات مجانية (5 دقائق)

استخدم **Neon** (الأسهل والمجاني):

1. اذهب إلى neon.tech وأنشئ حسابًا مجانيًا (يمكنك الدخول بحساب GitHub مباشرة)
2. بعد الدخول، اضغط **Create a project** واختر أي اسم
3. ستظهر لك صفحة فيها **Connection String** يبدأ بـ `postgresql://...` — انسخه كاملًا
4. هذا هو الرابط الذي ستضعه في `DATABASE_URL`

(البديل: supabase.com يعمل بنفس الطريقة تقريبًا)

## التشغيل محليًا

```bash
npm install
cp .env.example .env
```
افتح ملف `.env` وضع:
- `DATABASE_URL` → الرابط الذي نسخته من Neon
- `JWT_SECRET` → أي نص عشوائي طويل من عندك

```bash
npm start
```

الموقع سيعمل على `http://localhost:3000`، وعند أول تشغيل ينشئ الجداول تلقائيًا داخل قاعدة بياناتك على Neon.

## ⚠️ الأمر الأهم قبل النشر الفعلي: مصدر الإعلانات

هذا المشروع **جاهز تقنيًا** (خادم، قاعدة بيانات دائمة، مصادقة، محفظة) لكنه **لا يحتوي على إعلانات حقيقية** — الزر الحالي يحاكي "مشاهدة إعلان" بعدّاد فقط، بدون عرض إعلان فعلي ولا ربح فعلي من أي معلن.

لتشغيله كموقع حقيقي يدفع أموالًا فعلية، يلزمك:

1. **مصدر دخل حقيقي**: لا يمكنك استخدام Google AdSense لهذا النموذج لأنه يحظر "المكافأة مقابل مشاهدة/نقر الإعلان" صراحة ضمن سياساته. تحتاج بدلًا من ذلك شبكات متخصصة في هذا النوع (تُعرف بـ Rewarded/Offerwall Ads) مثل: AdGate Media، OfferToro، Adscend Media، أو Google AdMob Rewarded Ads (للتطبيقات). كل شبكة تعطيك كود/SDK لعرض الإعلان الحقيقي، وتحتاج ربطه مكان الدائرة الموجودة حاليًا في `public/app.js` و`routes/ads.js`.

2. **مطابقة الأرباح**: تأكد أن ما تدفعه للمستخدم (`RATE_PER_VIEW` في `.env`) أقل مما تقبضه أنت من الشبكة الإعلانية، وإلا ستخسر مالًا مع كل مشاهدة.

3. **مراجعة قانونية**: مواقع الدفع مقابل المشاهدة تخضع في كثير من الدول لتنظيمات تتعلق بالتحويلات المالية ومكافحة غسل الأموال، خصوصًا عند تفعيل السحب الفعلي للأموال. يُنصح باستشارة مختص قبل الإطلاق التجاري.

## ربط شبكة إعلانات حقيقية (Offerwall)

الموقع الآن يدعم الربط الحقيقي بشبكات "Rewarded/Offerwall Ads" (مثل AdGate Media، OfferToro، Adscend Media). الفكرة تختلف عن مجرد عرض إعلان على الصفحة:

1. تُظهر للمستخدم قائمة عروض (offerwall) داخل إطار (iframe) — مثل تحميل تطبيق، إكمال استبيان، أو مشاهدة فيديو
2. عندما يُنهي المستخدم عرضًا، **خادم الشبكة نفسه** (وليس متصفح المستخدم) يرسل طلبًا مباشرًا لخادمك يخبرك بذلك — يُسمى هذا **Postback** أو **Server-to-Server Callback**
3. خادمك يتحقق من صحة الطلب (بمفتاح سري) ثم يضيف الرصيد

هذا الأسلوب أكثر أمانًا من الاعتماد على توقيت المتصفح، لأن المستخدم لا يستطيع تزوير إتمام العرض من جهازه.

### خطوات التسجيل (مثال: AdGate Media)

1. اذهب إلى adgatemedia.com واطلب حساب **Publisher** (سيطلبون معلومات عن موقعك — قد يستغرق القبول من يوم لعدة أيام، فهذه الشبكات تُراجع كل ناشر يدويًا)
2. بعد القبول، من لوحة التحكم أنشئ "App/Placement" جديد، وستحصل على:
   - رابط الـ **Offerwall** الخاص بك (يحوي `pub_id` أو ما شابه)
   - مكان لإدخال رابط الـ **Postback URL**

3. **في ملف `.env` عندك:**
   - ضع رابط الـ Offerwall في `OFFERWALL_URL_TEMPLATE`، مستبدلًا معرّف المستخدم بـ `{USER_ID}` (كل شبكة تسميه شيئًا مختلفًا: `subid`، `s1`، إلخ — راجع وثائقهم)
   - اخترع مفتاحًا سريًا عشوائيًا وضعه في `OFFERWALL_SECRET`

4. **في لوحة تحكم الشبكة الإعلانية**، سجّل رابط الـ Postback الخاص بموقعك، بهذا الشكل:
   ```
   https://موقعك.com/api/postback/offerwall?user_id={subid}&amount={payout}&tx_id={transaction_id}&secret=نفس_المفتاح_من_env
   ```
   ⚠️ الأجزاء بين `{}` (مثل `{subid}`) هي "متغيرات" توفرها الشبكة نفسها لتضع بدلًا منها القيم الفعلية عند إرسال الطلب — ابحث في وثائق الشبكة عن الاسم الصحيح لكل واحد، لأنها تختلف قليلًا بين شبكة وأخرى.

5. أعد تشغيل الموقع. عند دخولك للوحة التحكم بحسابك، سيظهر تلقائيًا قسم "عروض حقيقية" بدل قسم المحاكاة.

### ملاحظات أمان مهمة
- الكود يمنع تلقائيًا احتساب نفس المعاملة (`tx_id`) مرتين، حتى لو أعادت الشبكة إرسال نفس الطلب
- تأكد أن `OFFERWALL_SECRET` طويل وعشوائي ولا تشاركه مع أحد
- بعض الشبكات تدعم أيضًا التحقق عبر IP whitelisting بدل السر النصي — إذا توفر هذا الخيار في لوحتهم فهو أكثر أمانًا، فعّله بالإضافة للمفتاح السري

## النشر (Deployment)

المشروع عبارة عن تطبيق Node.js عادي، يمكن نشره على أي من:

- **Render.com** أو **Railway.app**: ارفع الكود إلى GitHub، اربطه بالمنصة، حدد `npm start` كأمر تشغيل، وأضف متغيرات البيئة من `.env.example` في إعدادات المشروع — **الأهم هو `DATABASE_URL` بنفس رابط Neon**.
- **VPS عادي** (DigitalOcean، Hetzner، إلخ): استخدم `pm2` لإبقاء السيرفر يعمل: `pm2 start server.js`

بما أن قاعدة البيانات أصبحت على Neon (خارجية)، يمكنك الآن إعادة نشر الموقع أو تبديل منصة الاستضافة دون أن تفقد أي بيانات للمستخدمين.

## هيكل المشروع

```
watch-earn-app/
├── server.js           نقطة تشغيل الخادم
├── db.js               الاتصال بقاعدة بيانات PostgreSQL وإنشاء الجداول
├── middleware/auth.js   التحقق من تسجيل الدخول (JWT)
├── routes/
│   ├── auth.js          تسجيل / دخول
│   ├── ads.js           بدء/إنهاء مشاهدة إعلان
│   └── wallet.js        الرصيد والسحب
└── public/              الواجهة (HTML/CSS/JS)
```

## متغيرات البيئة (`.env`)

| المتغير | الوصف |
|---|---|
| `PORT` | المنفذ الذي يعمل عليه الخادم |
| `JWT_SECRET` | مفتاح تشفير الجلسات — **غيّره قبل النشر** |
| `DATABASE_URL` | رابط الاتصال بقاعدة بيانات PostgreSQL (من Neon أو Supabase) |
| `RATE_PER_VIEW` | المبلغ الذي يربحه المستخدم لكل مشاهدة |
| `AD_DURATION_SECONDS` | مدة الإعلان بالثواني |
| `MIN_WITHDRAW` | الحد الأدنى للمبلغ القابل للسحب |
| `MAX_VIEWS_PER_HOUR` | حد المشاهدات المسموح لكل مستخدم/ساعة |
